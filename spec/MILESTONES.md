# MILESTONES – משחק סיימון (Simon)

מסמך זה מחלק את מימוש המוצר לאבני דרך הניתנות לפיתוח, בדיקה ואישור בנפרד. מקורות האמת: `PRD.md` להתנהגות ולהיקף, `ARCHITECTURE.md` לפתרון הטכני, ו-`DESIGN.md` למבנה ולעיצוב, לרבות התמונות המקושרות אליו. אין להוסיף יכולות שאינן מופיעות במקורות.

## כללי ביצוע הפיתוח – Development Execution Rules

> **הנחיות מחייבות ל-AI המפתח:** יש לממש את ה-Milestones **לפי סדר הופעתם**. בסיום כל Milestone יש **לעצור**, להציג למשתמש את התוצר העובד, סיכום קצר של מה שמומש ותוצאות בדיקות מול **כל** סעיפי ה-Definition of Done (עובר/נכשל, עם הסבר אם יש מגבלה). **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**. במקרה של כשל יש לתקנו ולבדוק מחדש לפני בקשת האישור. אין לפרש אישור למילסטון אחד כאישור אוטומטי להמשך.

- לכל אורך הפיתוח: ממשק בעברית ו-RTL, Mobile-First לטלפון, שני מסכים בלבד (**בית**, **אודות**), ללא Backend, Database, Authentication או AI.
- יש להיצמד ל-React, TypeScript, Vite, CSS רגיל, `useReducer`, Web Audio API, `localStorage`, `canvas-confetti`, `vite-plugin-pwa`/Workbox, Vitest ו-React Testing Library, בהתאם לתפקידיהם במסמך הארכיטקטורה.
- בדיקות ידניות מתבצעות בדפדפן מובייל או באמולציית מובייל לפי ההתאמה; בדיקות התנהגות מערכת ההפעלה, אודיו ו-PWA מחייבות אימות במכשיר תומך ככל שניתן, ובדיקת HTTPS/Offline נעשית על Build פרוס. אין להציג בדיקה שלא בוצעה כאילו עברה.

## Milestone 1 – בסיס אפליקציה ושני מסכים מעוצבים

**שם ומטרה:** הקמת פרויקט Frontend עובד ושני המסכים בעיצוב עקבי, כדי שניתן יהיה להציג ולבדוק את מבנה המוצר לפני חיבור לוגיקת המשחק.

**מה יש לממש:**
- פרויקט React + TypeScript + Vite עם CSS רגיל, בדיקות בסיסיות ופקודות `dev`, `build`, `test` ו-TypeScript typecheck; קוד המקור מנוהל ב-Git Repository ב-GitHub.
- App Shell עם שני מסכים פנימיים בלבד, ניווט קבוע **"בית"** / **"אודות"**, `lang="he"` ו-RTL, ללא טעינת דף מחדש בעת מעבר.
- מבנה ה-UI לפי `DESIGN.md`: לוח Simon עגול בעל ארבעה אזורים (ירוק למעלה משמאל, אדום למעלה מימין, צהוב למטה משמאל, כחול למטה מימין), כותרת **"סיימון"**, חיווי שלב וכפתור **"התחל משחק"**; במסך אודות הסבר המשחק, אזור היסטוריה ריק וחיווי היעדר תוצאות.
- יישום השפה החזותית: Theme כהה מה-Mockups, צבעי ה-Style Guide וצבעי Background/Surface/Border שב-`DESIGN.md`, Typography מסוג Heebo עם Fallback (ארוז באפליקציה דרך `@fontsource/heebo`, ללא Google Fonts), חיווי **"שלב 1 מתוך 10"** לפני משחק, כפתורים, כרטיסים ופס ניווט; ללא כפתורי הגדרות או מתג סאונד.

**תוצר מצופה:** אפליקציית מובייל מקומית שניתן לפתוח ולנווט בה בין **בית** ל-**אודות**, עם מבנה ועיצוב קרובים להמחשות. בשלב זה הכפתור והלוח אינם מריצים עדיין משחק.

**Definition of Done:**
- [ ] `npm run build` ו-TypeScript typecheck מסתיימים בהצלחה; בדיקת Render/Navigation בסיסית עוברת.
- [ ] שני המסכים נפתחים ומעבר ביניהם אינו מרענן את הדף; אין מסך שלישי.
- [ ] מוצגים ארבעת אזורי הלוח במיקומים הנכונים, חיווי שלב וכפתור **"התחל משחק"**; מסך אודות מציג הסבר והודעת היסטוריה ריקה.
- [ ] כל הטקסטים הגלויים בעברית, כיווניות RTL, והתצוגה נוחה וקריאה ב-Viewport של Smartphone אנכי, ללא גלילה אופקית.
- [ ] לא נוספו יכולות שאינן ב-PRD, ואין Backend או Database.

## Milestone 2 – משחק מלא מקצה לקצה

**שם ומטרה:** מימוש סבב משחק שלם: התחלה, הצגת רצף, שחזור, התקדמות, ניצחון והפסד עם משוב חזותי וקולי.

**מה יש לממש:**
- Game Engine ו-`useReducer` עם מצבי `idle`, `presenting`, `awaitingInput`, `won`, `lost`; רצף אקראי המתחיל בצבע אחד וגדל בצבע נוסף בכל שלב, עד 10, כולל אפשרות לחזרות על צבע.
- Sequence Controller המציג את הרצף בקצב קבוע עם Glow וצליל נפרד לכל צבע באמצעות Web Audio API. קלט חסום בזמן ההצגה ופעיל רק בתור השחקן; תגובת צבע למגע כוללת Highlight וצליל.
- אימות סדר הלחיצות ללא הגבלת זמן: מעבר לשלב הבא רק לאחר שחזור מלא; טעות אחת מפסידה מיד; השלמת שלב 10 מנצחת. הצגת **"שלב X מתוך 10"**.
- מצבי סיום עם הודעת ניצחון/הפסד, צליל סיום מתאים וכפתור **"אישור"** שסוגר את ההודעה ומחזיר למסך הבית עם **"התחל משחק"**; קונפטי באמצעות `canvas-confetti` בניצחון בלבד. ציון תוצאת המשחק כמספר **השלבים שהושלמו** (0 בהפסד בשלב 1, 10 בניצחון).
- ניהול Effects ו-Timers ניתנים לביטול, והפעלה של `AudioContext` מתוך Gesture של המשתמש; טיפול גלוי בכשל התחלת אודיו ללא התקדמות שקטה מדומה.

- **מעבר ל"אודות" באמצע משחק – פתרון זמני עד Milestone 3:** ההשהיה וההמשך עדיין לא קיימים. באבן דרך זו, מעבר ל-**"אודות"** בזמן משחק פעיל מבטל את המשחק (עוצר הארה, צליל ו-Timers) ומחזיר את מסך הבית למצב **"לפני תחילת משחק"**, בלי לרשום תוצאה. זו התנהגות זמנית שתוחלף בהשהיה אמיתית ב-Milestone 3, ואינה נבדקת מול ה-PRD באבן דרך זו.

**תוצר מצופה:** משתמש יכול להתחיל ולסיים משחק אמיתי, להפסיד או לנצח, ולפתוח משחק חדש מיד. שמירת היסטוריה תתוסף ב-Milestone 4.

**Definition of Done:**
- [ ] משחק מתחיל בלחיצה על **"התחל משחק"**; אורכי הרצף בשלבים 1, 2 ו-10 הם בהתאמה 1, 2 ו-10, ורצף קודם נשמר כסיפא-לפני-התווספות (prefix) של הרצף הבא.
- [ ] ארבעת הצבעים מפיקים צלילים שונים והארה נבדלת; קצב הצגת הרצף אינו משתנה בין שלבים.
- [ ] לחיצות בזמן `presenting` אינן משפיעות; לחיצות נכונות מקדמות את הקלט, ולחיצה שגויה אחת גורמת להפסד ללא ניסיון נוסף.
- [ ] בדיקות מכסות הפסד בשלב 1 (0 השלמות), הפסד בשלב מתקדם, ניצחון לאחר השלמת שלב 10, מניעת שלב 11 ויצירת רצף חדש במשחק הבא (אחרי **"אישור"** ו-**"התחל משחק"**).
- [ ] בתום משחק מופיעים טקסט וצליל מתאימים; קונפטי מופיע בניצחון בלבד, ואינו מופיע בהפסד.
- [ ] רענון דף מבטל משחק פעיל ומציג מצב התחלה; אין שמירת מצב משחק פעיל לאחסון מתמיד.
- [ ] קצב ההצגה תואם לטבלת "קצב הצגת הרצף" ב-`DESIGN.md`; לחיצה שגויה משמיעה מיד את צליל הצבע שנלחץ, ושנייה אחר כך את צליל ההפסד יחד עם הודעת ההפסד.
- [ ] מעבר ל-**"אודות"** באמצע משחק אינו משאיר הארה, צליל או Timer פעילים (לפי הפתרון הזמני שלמעלה).

## Milestone 3 – השהיה וחידוש משחק

**שם ומטרה:** לאפשר מעבר לאודות, נעילת טלפון או יציאה זמנית לאפליקציה אחרת בלי לאבד את השלב הפעיל, תוך חידוש בשליטה מפורשת של השחקן.

**מה יש לממש:**
- החלפת הפתרון הזמני של Milestone 2 (ביטול משחק במעבר ל"אודות") בהשהיה אמיתית.
- מצב `paused` ומנגנון ביטול מלא של Playback, Timers, Highlights וצלילים פעילים במעבר למסך **"אודות"** או באירועי `visibilitychange`/`pagehide` רלוונטיים.
- שימור הרצף והשלב ב-Memory בלבד; איפוס קלט חלקי של השלב הנוכחי בעת השהיה.
- חזרה למסך הבית במצב מושהה עם כפתור **"המשך משחק"**. רק לחיצה עליו תציג מחדש את הרצף **המלא** של אותו שלב ותאפשר שחזור מתחילתו; ללא Resume אוטומטי.
- הגנה מפני Timers/Callbacks מיושנים, ריבוי Resume ולחיצות במהלך הצגת הרצף.

**תוצר מצופה:** משחק פעיל שומר על השלב שלו בזמן מעבר בין שני המסכים או בזמן הסתרת האפליקציה, וממשיך ידנית ללא שינוי ברצף.

**Definition of Done:**
- [ ] מעבר ל-**"אודות"** בזמן הצגת רצף ובזמן שחזורו משהה את המשחק ועוצר מיד הארה וצליל.
- [ ] חזרה ל-**"בית"** אינה מפעילה את הרצף מעצמה; הכפתור **"המשך משחק"** מופיע במשחק מושהה בלבד.
- [ ] לחיצה על **"המשך משחק"** מציגה מחדש את כל הרצף הקיים, גם אם חלק ממנו הוקש קודם; השלב אינו משתנה ואין תוספת צבע חדשה.
- [ ] הסתרת האפליקציה וחזרה אליה פועלות לפי אותו כלל השהיה/חידוש, ללא שינוי לא צפוי כתוצאה מ-Callback שבוטל.
- [ ] משחק שהושהה אינו נחשב הפסד, ורענון דף עדיין מאפס את המשחק הפעיל.

## Milestone 4 – היסטוריית משחקים ומחיקה מאושרת

**שם ומטרה:** להשלים יכולת משתמש של צפייה בעשרת המשחקים האחרונים וניהול ההיסטוריה המקומית ממסך אודות.

**מה יש לממש:**
- History Repository ב-`localStorage`, עם רשומות של תאריך ושעת סיום, מספר השלבים שהושלמו ותוצאה (`won`/`lost`); שמירת משחק בסיומו **פעם אחת בלבד**, ולא בעת השהיה/Refresh.
- שמירת עד עשרה משחקים בסדר החדש לישן, כולל הסרת הרשומה הישנה ביותר בהכנסת רשומה נוספת.
- מסך **"אודות"** מציג רשימת כרטיסי היסטוריה, חיווי ריק כשאין רשומות וכפתור **"מחק היסטוריה"** (מוצג רק כשיש רשומות).
- Dialog לאישור מחיקה עם **"ביטול"** ו-**"מחק"**, כולל עדכון התצוגה לאחר מחיקה.
- טיפול בקריאה/כתיבה/מחיקה לא זמינים ב-`localStorage` והצגת הודעת שגיאה בעברית, בלי לחסום משחק; בדיקות להגנה מפני רישום כפול ב-React Strict Mode.

**תוצר מצופה:** לאחר סיום משחק מוצגת תוצאתו במסך אודות, נשמרת בטעינה חוזרת וניתנת למחיקה רק לאחר אישור.

**Definition of Done:**
- [ ] ניצחון או הפסד מוסיפים בדיוק רשומה אחת עם זמן סיום, מספר שלבים שהושלמו ותוצאת **"ניצחון"**/**"הפסד"** בתצוגה.
- [ ] מעבר מסכים, השהיה, Refresh של משחק פעיל או יציאה באמצעו אינם מוסיפים רשומה.
- [ ] אחרי 11 משחקים קיימות לכל היותר 10 רשומות, בסדר מהחדש לישן; הן נשמרות לאחר Refresh באותו אחסון מקומי.
- [ ] **"ביטול"** לא משנה נתונים; **"מחק"** לאחר אישור מרוקן היסטוריה ומחזיר חיווי ריק.
- [ ] כשל אחסון אינו מונע משחק, ומוצגת הודעה מובנת בעברית כאשר פעולת שמירה או מחיקה נכשלת.
- [ ] בדיקות אוטומטיות מאמתות היסטוריה, מגבלת עשר, מחיקה, כשל אחסון ומניעת שמירה כפולה.

## Milestone 5 – PWA, Offline ופרסום ב-GitHub Pages

**שם ומטרה:** להפוך את המשחק השלם לאתר מובייל ציבורי שניתן להתקנה במכשירים תומכים ושממשיך לעבוד Offline לאחר טעינה מוצלחת.

**מה יש לממש:**
- יצירת אייקון האפליקציה לפי הגדרת ה-App Icon ב-`DESIGN.md` (קובץ SVG מקור + PNG בגדלים 192 ו-512, כולל Maskable ו-Favicon).
- וידוא שה-Repository `Simon` של המשתמש ציבורי לפני הפריסה; אם לא – עצור והדרך את המשתמש לשנות זאת. `base: "/Simon/"` ב-Vite.
- הגדרת `vite-plugin-pwa` עם Manifest בעברית, אייקוני התקנה ומשאבי Precache באמצעות Workbox `generateSW`, כולל הנכסים הנחוצים למסכים ולצלילים.
- ניהול עדכוני Service Worker ללא Reload כפוי באמצע משחק פעיל; טיפול ב-Cache ובנתיב הבסיס של GitHub Pages בהתאם למבנה ה-Repository.
- Workflow של GitHub Actions המבצע `npm ci`, typecheck, בדיקות, Build ו-Deployment אוטומטי של `dist/` אל GitHub Pages ב-HTTPS בעקבות שינוי בענף הפריסה; הגדרת Pages לשימוש ב-GitHub Actions.
- בדיקת המוצר המלא בנייד: מסכים, מגע, צלילים, השהיה/חידוש, היסטוריה, ניצחון/הפסד ו-Offline. התאמת הפריסה והנגישות הבסיסית להנחיות העיצוב, ללא הרחבת תכולת המוצר.

**תוצר מצופה:** כתובת GitHub Pages פעילה עם גרסה מלאה של המשחק; משתמש יכול לפתוח את האתר במובייל, להתקינו במכשיר תומך ולשחק ללא חיבור אחרי שהמשאבים נשמרו.

**Definition of Done:**
- [ ] Workflow ב-GitHub Actions עובר בדיקות ו-Build ומפרסם את האתר אוטומטית לאחר Push לענף המוגדר, ללא פריסה ידנית חוזרת.
- [ ] האתר נטען בכתובת GitHub Pages דרך HTTPS, ומשאבים/ניווט פועלים תחת נתיב הפרויקט ללא שגיאות 404.
- [ ] Manifest ו-Service Worker תקינים; אפשרות התקנה קיימת בדפדפן/מכשיר שתומך בכך.
- [ ] לאחר טעינה ראשונית מלאה ו-Precache מוצלח, ניתוק האינטרנט אינו מונע פתיחה מחדש, משחק, השמעת צלילים, ניווט או צפייה בהיסטוריה השמורה.
- [ ] עדכון גרסה אינו מרענן או מפסיק משחק פעיל בכפייה.
- [ ] בדיקות Regression של עשרת השלבים, כישלון ראשון, קונפטי בניצחון בלבד, השהיה וחידוש, שמירת עשר תוצאות ומחיקה מאושרת עוברות; נבדקה תצוגת Smartphone אנכית בעברית/RTL.

---

**סיום הפרויקט:** אחרי שהמשתמש מאשר במפורש את Milestone 5, כל יכולות ה-PRD מכוסות. אין להוסיף שלבי פיתוח, יכולות או שירותים מעבר למסמכי המקור ללא בקשה חדשה.
